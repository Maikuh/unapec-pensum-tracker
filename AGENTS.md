# AGENTS.md

## Commands

All commands use **bun** as the package manager.

```bash
bun dev            # Start dev server
bun build          # Static export build (outputs to /out)
bun lint           # Biome check
bun lint:fix       # Biome check with auto-fix
bun typecheck      # tsc --noEmit (also covers test files; `next build` fails on test type errors)
bun format         # Biome format with auto-fix
bun test           # Vitest (watch mode)
bun test:run       # Vitest (single run)
bun test:coverage  # Vitest + per-file coverage thresholds (what CI runs)
bun test:e2e       # Playwright E2Es
bun test:all       # Run all tests (unit, component and e2e)
bun sync:pensums   # Regenerate lib/data/pensums.json from UNAPEC (requires internet; `-- --refresh-names` to take API names as-is)
```

To run a single test file: `bun vitest run lib/graph/prerequisite-graph.test.ts`

## Code Style

Uses **Biome** (not ESLint/Prettier): tabs for indentation, single quotes, no semicolons. Run `bun lint:fix` before committing.

## Architecture

**Static export app** deployed to GitHub Pages. `next.config.ts` sets `output: 'export'` and `basePath: '/unapec-pensum-tracker'`. No server-side rendering — all data is baked in at build time.

### Data layer

All pensum (curriculum) data lives in [`lib/data/pensums.json`](lib/data/pensums.json) as a static JSON array of `Pensum` objects. **Do not hand-edit this file** — it is generated by `scripts/sync-pensums.ts`. The type hierarchy (`Pensum → Period → Subject → ElectiveOption`) is defined in [`types/`](types/). [`lib/data/pensum-pages.ts`](lib/data/pensum-pages.ts) maps pensumCode to official UNAPEC URLs and is also auto-generated.

The sync script discovers programs from UNAPEC's "Programas de grado" index (each page embeds `const codigoPesum = "..."`), so new careers are picked up automatically. Pure parsing lives in [`scripts/lib/pensum-parsers.ts`](scripts/lib/pensum-parsers.ts) (unit tested). It merges with the previous snapshot:

- Subject names from the previous snapshot win: the API now truncates names to 30 chars and abbreviates/misspells many of them.
- Pensums UNAPEC stops listing are kept and flagged `legacy: true` (shown with a notice and an "Anterior" tag) so students don't lose progress.
- A pensum's `date` only changes when its content changes, so re-running the sync is idempotent.

Some pensums list prerequisites that aren't part of the pensum (e.g. `ENG008` in CPM11). [`split-external-prerequisites.ts`](lib/helpers/split-external-prerequisites.ts) strips those before any logic runs so they don't make subjects unselectable; they're still shown as dashed badges.

### Prerequisite graph

[`lib/graph/prerequisite-graph.ts`](lib/graph/prerequisite-graph.ts) builds a bidirectional DAG from a flat `Subject[]`:

- `prerequisites`: code → set of codes required before this subject
- `dependents`: code → set of codes this subject unlocks

The graph is built in [`pensum-content.tsx`](components/pensum-content.tsx) via `useMemo` and threaded down to components. Logic that operates on this graph lives in [`lib/helpers/`](lib/helpers/) (cascade removal, selectable subjects, prerequisite checking) and [`lib/graph/traversal.ts`](lib/graph/traversal.ts).

### State management

Zustand store in [`lib/store/use-selected-subjects.ts`](lib/store/use-selected-subjects.ts) with `persist` middleware (localStorage key `selectedSubjects`). The store uses `skipHydration: true` — [`components/store-initializer.tsx`](components/store-initializer.tsx) triggers rehydration on mount and [`useHydrated()`](lib/store/use-hydrated.ts) reports when it has finished (always `false` on the server). Gate logic that must run against persisted data on it — e.g. `PensumContent` calls `syncPensum` once hydrated to refresh saved subjects against the current pensum data (saved entries are full `Subject` copies and go stale when data changes).

### Routing

Two routes:

- `/` — home page with career search
- `/pensums/[id]` — pensum view, statically generated for every pensumCode via `generateStaticParams()`

### Bundle size rules

- **Never import `lib/data/pensums.json` from a Client Component** — it ships every pensum to the browser. Use [`pensumSummaries`](lib/data/pensum-summaries.ts) in a Server Component and pass it down (see `app/layout.tsx` → `Navbar`).
- **Analytics:** import `posthog` from [`@/lib/analytics`](lib/analytics.ts), never from `posthog-js`. The app uses the slim PostHog build initialized in `instrumentation-client.ts`; importing `posthog-js` directly gives an uninitialized instance and re-adds the full bundle.

### UI components

shadcn/ui components in [`components/ui/`](components/ui/) backed by **`@base-ui/react`** (not Radix UI). Use the existing shadcn setup when adding new components.
